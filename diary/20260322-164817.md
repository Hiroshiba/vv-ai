## レビュー対応

- backend に関係なく、まず `load_latest_session_manifest(...)` の結果を優先し、既存のローカル継続経路を維持するよう修正した。
- GitHub remote 復元はローカル manifest が無い場合だけ使うようにした。
- `resolve_age_secret_key(...)` は remote artifact を見つけたあとに呼ぶよう順序を修正した。

## 見逃しの考察

- 最初の実装では requirements の `repo 全体から名前 prefix 一致で最新 artifact を取得` に意識が寄り、現在の保存経路がまだローカル only である事実を軽く扱ってしまった。
- その結果、将来の runner 復元経路を先に成立させることを優先し、既存の local/manual 継続という今すでに成立している振る舞いを壊した。
- さらに、secret 解決も復元フローの一部としてまとめて前倒しで置いてしまい、復号が本当に必要になる条件を分離して考えられていなかった。
- 今後は新しい復元経路を足すとき、既存の保存元と既存の再開経路が何かを先に表で整理し、missing resource と missing secret のどちらが product 上の先行条件かを順序まで含めて確認する。
