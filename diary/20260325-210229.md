## 受けたレビュー

- `output_file.exists()` の条件が常に `True` になり、`proc.stdout` へのフォールバックが到達不能になっていた。`NamedTemporaryFile(delete=False)` がファイルを即座に作成するため、Codex が `-o` に書き込まなかった場合にサイレントに空文字列になる。`file_content = output_file.read_text(); result_text = file_content if file_content else proc.stdout` に修正した。
- `prompt` を `--` セパレータなしで引数リストに追加していたため、`-` で始まる instruction を Codex CLI がフラグとして解釈する可能性があった。`base_options` の末尾に `"--"` を追加して修正した（`resume` 側も同様）。

## 見逃しの考察

- `NamedTemporaryFile(delete=False)` でファイルが作成済みになることを意識せずに `exists()` チェックを書いてしまった。tempfile の生成方式によって「ファイルが存在する = Codex が書いた」が成立しない点を見落としていた。ファイル存在チェックではなく内容チェックで判定すべきというのは、空ファイルと未書き込みを区別する基本的な考え方だった。
- `--` セパレータは CLI 引数を扱う際の基本パターンだが、ユーザー入力をそのまま末尾に渡す実装で見落とした。引数リストにユーザー入力を追加する箇所では常に `--` の要否を確認する必要がある。

## 手こずったこと

- Codex CLI の `--json` 出力が JSONL 形式であること、かつそのスキーマがドキュメントに明示されていないため、`_parse_codex_jsonl` は best-effort の実装になっている。実際の出力を確認後に更新が必要。
- `codex exec resume` の `-o` フラグが help に含まれているか確認が必要だったが、実際に `codex exec resume --help` を実行して確認できた。
