# dry-run と finally-save 保証のテストを実装

## レビュー内容

1回目のレビューで SHOULD-FIX 1件を受けた。
`test_dryrun_suppresses_implement_issue_push` で `push_branch` の呼び出し抑制を明示的に検証していなかった。
`github_client.create_pull_request` の非呼び出しのみで間接的にカバーしていたが、将来 dry-run チェック位置が変わった場合に検出できないリスクがあった。

2回目のレビューでは指摘なし。

## 見逃しの考察

PR 起点のテストでは `push_branch` を patch していたのに、Issue 起点では同じ観点を漏らした。
テストを書く際に「同種の関数呼び出しが複数箇所ある場合は同じ検証パターンを適用する」という意識が不足していた。

## 手こずったこと

`SavedSessionArtifact`, `SavedMetricsArtifact`, `SavedReportArtifact` の Pydantic モデルが `extra="forbid"` で必須フィールドが多く、テスト用のダミーインスタンス作成で3回バリデーションエラーが出た。
最終的に `save_execution_artifacts` はモックしているため返り値に実体は不要と判断し、`MagicMock(spec=SavedExecutionArtifacts)` で解決した。
