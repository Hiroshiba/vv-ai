# 20260404-003155

## 実施内容

Codex provider で `auth.json` を使えるようにした。
workflow に `VV_CODEX_AUTH_JSON` と `VV_CODEX_HOME` を追加し、GitHub Actions から Codex の subscription 認証情報を注入できるようにした。
provider 解決と実行層の両方で `auth.json` を認識するように変更した。

## レビューと対応

`VV_OPENAI_API_KEY_FILE` が空ファイルのときに `auth_home_env` の確認へ進まず、Codex provider を拒否してしまう指摘を受けた。
`_has_provider_secret` を修正し、空ファイルでも `VV_CODEX_HOME/auth.json` を見に行くようにした。

未使用の `_resolve_api_key` が残っている指摘を受けた。
使用箇所がないことを確認して削除した。

`VV_OPENAI_API_KEY_FILE` が存在しないパスを指すときの診断が弱くなっていた指摘を受けた。
`_try_resolve_api_key` を修正し、対象パスを含む具体的なエラーを出すようにした。

なお、`provider.py` と `provider_execution.py` で `VV_OPENAI_API_KEY_FILE` の解決契約に不整合が残っている。
`provider.py` は壊れた file env があっても value env を見に行くが、`provider_execution.py` は即例外を投げる。
この既知事項は未修正のまま今回の commit に含める。

## 見落とした原因

provider 選択層と実行層を別々に修正し、同じ secret 解決契約として横並びで確認しきれなかった。
空ファイルとファイル不在を分けて考えた一方で、壊れた file env が value env にフォールバックしてよいかを最後まで統一できていなかった。

## 手こずったこと

Codex の ChatGPT subscription 認証を GitHub Actions へ持ち込む前提が API キー方式と異なるため、`auth.json` の扱いを workflow と実行コードの両方で揃える必要があった。
GitHub-hosted runner では `auth.json` の更新書き戻しが将来的に必要になるため、その TODO を残しつつ今回の変更範囲を絞った。
