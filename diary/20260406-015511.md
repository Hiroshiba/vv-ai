## 見落としの考察

`G-Live-10` で artifact の中身を確認した時点で、保存された artifact を次 run の preflight が本当に検索できるかまでは検証できていなかった。
保存と検索を別問題として切り分けず、保存できていれば復元側も動く前提で先に進んでしまった。

また、workflow run の確認時に `24005870373` と `24005955329` を取り違えた。
`gh workflow run` の直後に対象 run ID を確定せず、`gh run list` の結果から目視で追ったため、別 run を今回の実行結果として扱ってしまった。

防止策としては、毎回以下を固定手順にするべきだった。

- `gh workflow run` の直後に最新 `workflow_dispatch` run を 1 件だけ取得して run ID を確定する
- 以後の確認は必ずその run ID を引数にした `gh run watch` と `gh run view` だけで行う
- `createdAt` と `event` を毎回照合し、今回の実行時刻と一致することを確認してから結論を書く
- success / failure の判断前に run ID をメモへ残し、その ID が回答中も一貫しているか見直す

## 手こずったこと

途中で別の workflow run `24005870373` を見てしまい、今回対象の run と取り違えた。
その後に最新 run `24005955329` を確認し直して `G-Live-10` の成功を確定した。

今回の失敗はその run とは別で、`24006089483` の `inherit` 実行で起きている。
