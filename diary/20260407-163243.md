# Claude Provider の gh コマンド失敗原因の特定と修正

## 作業内容

G-CL-10 テストで Claude が `gh issue view` を「承認が必要」として実行できない問題を調査し、修正した。

## 調査の経緯

最初は sandbox が起動していないと仮定して bubblewrap/socat のインストールと `failIfUnavailable: true` を追加した（前回）。しかし修正後も同じ症状が続いた。

次にセッション artifact を age で復号して JSONL を調査した。そこで実際のツール呼び出しと結果が判明した:

1. Claude が `Bash(gh issue view 1)` を実行
2. `apply-seccomp: Permission denied`（exit 126）
3. Claude が `dangerouslyDisableSandbox: true` で再試行
4. `allowUnsandboxedCommands: false` により `This command requires approval` で拒否

原因は anthropics/claude-code#43367 の既知リグレッション。v2.1.92 で `apply-seccomp` バイナリの実行ビットが npm install 時に落ちるバグ（未修正・open）。

## 修正

`Install AI CLIs` ステップに以下を追加:

```yaml
# TODO: anthropics/claude-code#43367 workaround: v2.1.92 で実行ビットが落ちる。修正版がリリースされたら削除する
chmod +x /usr/local/lib/node_modules/@anthropic-ai/claude-code/vendor/seccomp/*/apply-seccomp || true
```

## レビュー

指摘なし。

## 手こずったこと

セッション artifact の活用を思いつくまでに時間がかかった。ログに Claude Code 内部のツール実行ログ（stderr）が出ないため、原因が全く見えなかった。artifact を age で復号して JSONL を読むという調査手法は有効で、今後も活用できる。

また、ユーザーが age キーを変更してテスト再実行を提案したが、これは原因とは無関係だった。思い込みで調査の方向性を誤りかけた。

sandbox が「起動している」と「正常に動作している」は別物であることも教訓になった。bubblewrap の名前空間分離と seccomp のシステムコール制限は独立した層で、前者が成功しても後者が失敗する場合がある。
