# Report

## Summary
`vv-ai.yml` の設定モデルと読み込み処理を追加し、後続タスクで共通利用できる設定入口を整備した。レビュー指摘を反映し、`provider_priority` 省略時は `codex -> claude` を既定値として補完するように修正した。

## Changes
- `pyproject.toml` に `pydantic` と `PyYAML` を追加した。
- `src/vv_ai/config.py` を追加し、`VVAIConfig`、`ProviderName`、`load_vv_ai_config()`、設定読込用例外を実装した。
- `allowed_users` の空文字拒否、未定義キー拒否、YAML マッピング必須、設定ファイル未配置時の明示エラーを実装した。
- エラーメッセージを日本語に統一した。
- `provider_priority` は省略可能にし、既定値 `["codex", "claude"]` を設定した。
- `plan.md` の `vv-ai.yml` 設定モデル定義タスクを完了済みに更新した。

## Decisions
- このタスクでは CLI への配線までは行わず、後続の入力正規化から使える独立モジュールとして切り出した。
- `vv-ai.yml` 自体は必須ファイルとして扱い、未配置時は即エラーにする方針を維持した。
- 設定値の typo を早く検出するため、未定義キーは許容せず validation error にする方針にした。

## Validation
- `UV_CACHE_DIR=/tmp/uv-cache uv run python` で正常な `vv-ai.yml` を読み込み、設定値を取得できることを確認した。
- `provider_priority` を省略した `vv-ai.yml` で既定値 `["codex", "claude"]` が補完されることを確認した。
- `vv-ai.yml` 不在時に日本語メッセージの `VVAIConfigFileNotFoundError` が発生することを確認した。
- `allowed_users` に空白のみを指定した場合に日本語メッセージの設定エラーになることを確認した。
- `provider_priority` の不正値と未定義キーで設定エラーになることを確認した。

## Risks / Open Questions
- validation error の詳細本文はまだ上位へ透過しておらず、CLI 統合時にどこまで利用者へ見せるかは次タスク以降で決める必要がある。
- `provider_priority` の重複指定や順序補正は未対応で、必要なら provider 選択ロジック実装時に扱う。

## Next Actions
- 次の未完了タスクである「CLI / event payload を受ける入力モデルを定義する」に着手する。
- `vv-ai.yml` 読み込み処理を後続の入力正規化フローへ接続する。
