## 実施内容

plan.md セクション 15「Codex Provider テスト」を完走した。途中で2件のバグを修正した。

### バグ 1: shell_environment_policy の設定エラー

`provider_execution.py` で codex CLI に渡す設定が `inherit=include_only` という無効な値を使っていた。

正しい `include_only` の使い方は `inherit` の値としてではなく、別フィールドとして渡すものだった。codex CLI の仕様を context7 と実テストで確認し、`inherit="all"` + `include_only=[...]` がホワイトリスト方式として正しいと判断した。

テストで確認した動作:
- `inherit="none"` + `include_only` → `include_only` が空マップをフィルタするだけで機能しない
- `inherit="all"` + `include_only` → 全変数を読み込んでからフィルタ。API KEY 漏洩なしを実テストで確認

### バグ 2: ローカル Issue の implement でアサーションエラー

`command_handler.py:78` で `assert target.number is not None` が失敗した。ローカル Issue は `target.number=None` で `target.local_id="test-issue-1"` が識別子になるため。

`generate_implement_branch_name` の引数を `int` から `str` に変更し、呼び出し側でローカルなら `local_id`、GitHub なら `str(number)` を使うよう修正した。

## レビュー内容

レビューで `shell_environment_policy` の設定方式について MUST-FIX が2回出た。

1回目: `inherit="core"` は中身が不透明でホワイトリスト方式でないという指摘 → 正当。`inherit="all"` + `include_only` に修正した。

2回目: `inherit="all"` は全変数を子プロセスに渡すのでセキュリティ違反という指摘 → 事実誤認と判断し対応しなかった。`inherit` は初期マップ構築の設定であり、`include_only` フィルタが後続ステップで適用される。実テストで API KEY 非漏洩を確認済み。

## 見逃しの考察

`include_only` を `inherit` の値として書いてしまったのは、codex CLI の実装を調べずに推測で書いたため。今回も最初の調査では `inherit="core"` + `ignore_default_excludes=false` という方式を選んだが、`inherit="none"` + `include_only` という間違った方式に一度変えてしまった。`inherit` と `include_only` の関係（ステップ順）を正確に理解せず実装したことが原因。

## 手こずったこと

`inherit="all"` + `include_only` の組み合わせがセキュリティ的に正しいことを説明するのが難しかった。レビュアー（自動）が `inherit="all"` という文字面でセキュリティ問題と判断したが、実際には `include_only` との組み合わせで初めて意味をなすため、アルゴリズムのステップ順序を理解しないと判断できない。実テストで `NO_KEY_FOUND` を確認したことが決め手になった。
