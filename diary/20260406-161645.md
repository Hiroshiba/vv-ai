# 日誌 2026-04-06 16:16

## 実施内容

前回の日誌で判明した G-Live-50 の失敗を修正した。

修正内容: `command_handler.py` L53 の `github_client` 初期化条件に `command.command == "issue"` を追加し、L446-448 のサイレントスキップ分岐を `assert` に置換した。

## 原因の詳細

`github_client` の初期化が `_is_github_target(target)` に依存していた。`issue` コマンドは target を持たないため `target=None` → `github_client=None` となり、`_handle_issue_post_execution` で `[local]` 扱いされ Issue 作成がスキップされていた。

影響範囲を確認したところ、バグは「workflow_dispatch + issue コマンド + target_url なし」のケースのみ。issue_comment トリガーでは target が存在するため問題なし。reply/plan/review/implement も target 必須のため問題なし。

## 修正方針の選択

日誌には `_handle_issue_post_execution` 内でフォールバックする案が書かれていた。しかし `_post_fork_patch_fallback` のフォールバックは fork push 失敗のエッジケース向けであり、`issue` コマンドは通常フローで `github_client` が必要。L53 の初期化時に作るのが自然と判断した。
