# Issue #22: implement時にfork元ブランチを起点にする

## レビュー内容

3回のレビューを受けた。

- レビュー1回目: SHOULD-FIX 1件。`create_and_checkout_branch` の `start_point` 引数にデフォルト値 `None` がある（規約違反）→ デフォルト値を除去して修正
- レビュー2回目: NOTE 2件
  - upstream URL の `.git` suffix 違いで `GitOpsError` になる可能性 → `_normalize_git_url` を追加して URL 正規化後に比較するよう修正
  - PRベースブランチとブランチ起点が異なる（fork が遅れている場合に diff にノイズが混じる） → Issue #22 の設計通りのため対応しない
- レビュー3回目: NOTE 1件（PRベースブランチの件を再指摘）→ 設計上の意図であるため対応しない。全 CHECKED 項目は問題なし

## 見逃しの考察

- `start_point` のデフォルト値: 呼び出し側が常に引数を渡すためデフォルト値が不要であることを見落とした。「`None` で呼べると便利かも」という習慣的な思考でデフォルト値を付けてしまった。規約（デフォルト値禁止）を実装時に意識できていなかった
- URL の `.git` suffix 問題: ローカル実行で upstream を手動登録する場合を想定できていなかった。GitHub Actions では毎回クリーンな環境のため問題にならないが、ローカルユーザーへの影響を考慮していなかった
