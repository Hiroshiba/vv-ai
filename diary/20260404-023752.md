## 発見したバグ

### Codex: セッションファイルが artifact に含まれない

`_execute_codex` では `provider_session_path=None` が固定されている（`provider_execution.py:345`）。
そのため session artifact の tar に Codex のセッションデータが入らない。

Codex は `codex exec resume <session_id>` でセッションを再開するが、これはサーバー側（OpenAI API）ではなくローカルの `~/.codex/sessions/` に保存されたファイルを参照する（`codex exec resume --help` で確認。`--ephemeral` オプションがあることからもローカル保存が前提とわかる）。
GitHub-hosted runner は ephemeral なので毎回 `~/.codex/` が消え、thread_id だけ持っていても再開不可。

### Claude: 復元したセッションファイルが配置されない

`_execute_claude` は `ready_execution.resolved_session.restored_provider_session_path` を参照していない。
artifact には `provider-session/` ディレクトリとして Claude のセッションファイルを保存しており、`RestoredSessionArtifact.provider_session_path` に展開先パスが入る（`session_artifact.py:303`）。
しかし `_execute_claude` 実行前にそのファイルを `~/.claude/projects/.../<session_id>.jsonl` へ配置するコードがないため、`claude --resume <session_id>` は毎回失敗する。

### 両者共通

GitHub Actions ワークフローにはセッション復元に関するステップはない。セッション保存・復元は Python コード（`session.py`, `provider_execution.py`）に閉じており、ワークフロー側では何もしていない。
