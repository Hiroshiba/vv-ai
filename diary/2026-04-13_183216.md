# Issue #8 sync_fork_branch.py 実装

## レビュー内容

- `git fetch origin upstream` が upstream リモートを fetch していないバグ → `git fetch origin` と `git fetch upstream` の2回に分割して修正
- `_run` のデフォルト引数が規約違反 → キーワード専用引数に変更し全呼び出し元を明示的に修正
- 実装詳細コメント4件が規約違反 → 削除
- 一時ブランチが conflict 時に残留する → エラーメッセージに `git branch -D <tmp>` のクリーンアップ手順を追記
- `_cherry_pick_and_push` で `remote == "upstream"` のとき remote tracking ref を直接 checkout して detached HEAD になり cherry-pick 済みコミットが届かないバグ → 一時ローカルブランチ経由に変更
- `main()` に docstring がない → 追加
- `_commits_not_in` の docstring が実装と逆の順序を示していた → 「新しい順」に修正

## 見逃しの考察

- `git fetch origin upstream` のミス: git の `fetch <remote> [<refspec>]` 構文を誤解していた。`upstream` をリモート名ではなく refspec として渡してしまった。複数リモートを fetch する場合は別々に呼び出す必要があることを意識できていなかった。
- `_cherry_pick_and_push` の detached HEAD バグ: `_force_replace` では一時ブランチを使っている設計を認識していたが、`_cherry_pick_and_push` に同じパターンを適用しなかった。remote tracking ref を直接 checkout すると detached HEAD になることは知識として持っていたが、実装時に見落とした。
- `_run` デフォルト引数: 規約を把握した上で「内部メソッドだから許容されるかもしれない」と判断を誤った。規約に例外はない。

## 手こずったこと

特になし。レビュー指摘がすべて明確で、修正方針の迷いはなかった。
