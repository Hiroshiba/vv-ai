# breakdown コマンドのファイル書き出し方式への変更

## レビュー内容

5件の指摘（MUST-FIX × 3、SHOULD-FIX × 2）。

- MUST-FIX: `shutil.rmtree` に渡す `breakdown_dir` が `hiho_temp/` 配下か未検証 → 任意ディレクトリを削除できる問題。`is_relative_to(hiho_temp)` によるバリデーションを追加して修正した
- MUST-FIX: `is_relative_to` が `..` を字句比較するため `hiho_temp/../diary` が通過する問題。`.resolve()` で正規化してから比較するよう修正した
- MUST-FIX: `glob("*.md")` がシンボリックリンクをリストし、`read_text()` がシンボリックリンクを辿るため、symlink 経由でリポジトリ外のファイル（secrets等）を Issue 本文として投稿できる問題。`is_symlink()` チェックを追加し `CommandError` を raise するよう修正した
- SHOULD-FIX: `ignore_errors=True` がクリーンアップ失敗を握りつぶす問題。リポジトリ規約違反。ユーザーの「hiho_temp を削除しなくて良い」という方針を受けてクリーンアップ処理ごと削除した
- SHOULD-FIX: `hiho_temp/` が `.gitignore` 未記載のため、ローカルで breakdown → implement の順に実行すると一時タスクファイルが `git add -A` で commit に混入する問題。`.gitignore` に `hiho_temp/` を追加した

## 見逃しの考察

- シンボリックリンク経由のファイル読み取りは、ディレクトリパスの検証だけでは防げない点を見落とした。ディレクトリを `hiho_temp/` 配下に制限しても、その中のファイルが外を指すシンボリックリンクであれば制限を迂回できる
- `is_relative_to` が字句比較である点は知識として持っていなかった。`..` を含むパスを正規化せずに渡すと期待通りに動かない。パスのバリデーションには常に `.resolve()` を組み合わせる必要がある
- `shutil.rmtree` のような破壊的操作は、操作対象パスの出所（今回は AI 出力）まで遡って検証する習慣がなかった。信頼できない入力から得たパスには追加のガードが必要

## 手こずったこと

- `is_relative_to` の `..` 挙動の確認のため `uv run python` で動作検証が必要だった。Python 標準ライブラリの動作を思い込みで判断すると誤った実装になる
