# confirm コマンドの追加と README / requirements.md 整理

## レビュー内容

4ラウンドのレビュー、合計5件の MUST-FIX と2件の SHOULD-FIX。

- MUST-FIX: `input.py` の `CommandName` Literal と `_COMMAND_NAMES` に `confirm` が含まれていなかった。CLI の argparse は通過するが Pydantic validation で失敗し、コメント起動では `confirm` が reply の instruction として扱われた。両方に追加して修正した
- MUST-FIX: `README.md` の `--command` 一覧に `confirm` を載せていたが、上記の未追加により実際には動作しない状態だった。input.py 修正で解消した
- MUST-FIX: `workflow_dispatch` の command choices に `confirm` がなかった。GitHub Actions から手動実行できない状態。choices に追加してワークフロー順に並べ直した
- SHOULD-FIX: `resolve.py` の target 必須コマンドのセットに `confirm` が含まれていなかった。target 未指定時に早期エラーにならず後段で失敗していた。セットに追加した
- SHOULD-FIX: `requirements.md` のサブコマンド一覧・コマンド例・workflow_dispatch 入力・target 必須コマンドリスト・instruction 省略ルール・セッション共有コマンドリスト・SUCCESS METRICS の7箇所に `confirm` が欠けていた。全箇所を追記した

## 見逃しの考察

- `input.py` の `CommandName` と `_COMMAND_NAMES` の存在を事前調査で把握できなかった。cli.py の argparse choices だけ見て「追加できた」と判断してしまった。コマンド追加時は入力バリデーション層（型定義・セット・argparse・ワークフロー定義）を横断的に確認する必要がある
- `resolve.py` の target 必須コマンドのセットも見落とした。「コマンドを追加したら関連する検証ロジックも更新する」という当たり前のチェックが抜けた
- `requirements.md` の更新漏れは計画段階でスコープに入っていなかった。仕様ドキュメントは実装と同時に更新すべきだった
