# 日誌 2026-04-02

## 実施内容

GitHub Secret `VV_CLAUDE_SETTINGS` で Claude Code の追加設定を注入できる機能を実装した。

### 変更内容

- `provider_execution.py` に `_CLAUDE_EXTRA_SETTINGS_ENV = "VV_CLAUDE_SETTINGS"` 定数を追加
- `_build_claude_settings` の引数に `extra_settings_json` を追加し、`--settings` JSON にマージする形で注入
- セキュリティ設定（`allowUnsandboxedCommands` / `permissions` / `sandbox` / `apiKeyHelper`）はマージ後に強制上書きして保護
- `.github/workflows/vv-ai.yml` の `Run vv-ai` ステップに `VV_CLAUDE_SETTINGS` env を追加

### 設計判断

settings の `env` フィールドで値を渡しても、Claude 内のコードから `printenv` で見えることを tmux + claude で実証した。env var は Claude プロセスの環境に設定されるため、真の秘匿は不可能。TODO コメントで記録し、将来 localhost proxy 経由で隠す案を plan.md に追加した。

セキュリティ設定の上書き防止は「ユーザー設定を土台にしてセキュリティ設定を最後に適用」する方式にした。個別キーを再上書きする方式は漏れが発生するため採用しなかった。

## レビュー内容

- 最初の実装（個別キー再上書き）に対し「まだ脆弱では」と指摘を受けた。`permissions.deny` / `sandbox.filesystem.denyRead` / `apiKeyHelper` 等も上書き可能だった
- セキュリティ設定をオブジェクト単位で丸ごと後置きする方式に修正した

## 見逃しの考察

settings env の可視性を事前にテストせず「隠せるかもしれない」と見込みで設計を進めてしまった。テストを先にやっておけば設計の前提が固まっていた。
