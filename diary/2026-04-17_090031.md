# Issue #21 修正: git push 403 対応

## 作業内容

GitHub Actions で `git push` が 403 になるバグを修正した。

- `actions/checkout@v4` に `persist-credentials: false` を追加し、read-only トークンが git 認証情報として残らないようにした
- `git_ops.py` の `push_branch` / `try_push_current_branch` に `token: str | None` 引数を追加
- `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*` 環境変数で HTTP Authorization ヘッダーを git サブプロセスに注入する `_build_push_env` を実装
- `command_handler.py` の後処理ハンドラに `env: Mapping[str, str]` を追加し、`env.get("GITHUB_TOKEN")` を push 関数に伝播

ユーザー指示により localhost proxy（API キー秘匿）の実装は取り下げた。

## レビュー内容

3回のレビューを受けた。

- レビュー1回目: SHOULD-FIX 1件。`anthropic_proxy.py` の HTTPError 時にレスポンスヘッダーを転送していない → `exc.headers.items()` を転送するよう修正（その後 proxy 実装ごと削除）
- レビュー2回目: NOTE 1件。`proxy_server.server_close()` が欠落 → `shutdown()` の後に `server_close()` を追加（その後 proxy 実装ごと削除）
- レビュー3回目（proxy 削除後）: 全項目 CHECKED。MUST-FIX / SHOULD-FIX / NOTE なし

## 見逃しの考察

- HTTPError 時のレスポンスヘッダー転送漏れ: 正常系ヘッダーの転送は実装していたが、エラー系を同様に扱う必要があることを見落とした。エラーパスを正常パスと対称的に扱う意識が不足していた
- `server_close()` の欠落: `shutdown()` でサーブループを停止すれば完了と思い込んでいた。HTTPServer のライフサイクルが `shutdown()` と `server_close()` の2ステップであることを把握していなかった

## 手こずったこと

- ユーザーから proxy 実装を取り下げるよう指示を受けた。実装・レビュー対応後の巻き戻しだったため、`_resolve_api_key_file_path` の復元や TODO コメントの戻しなど細かい差分の管理が必要だった
- `_handle_implement_issue_post_execution` の引数追加時に、既存のパラメータと重複するミスがあった（Edit ツールの挿入位置のずれ）。テストで即座に検出できた
