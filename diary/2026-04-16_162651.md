# Issue #17 対応: Context7 MCP をランナー上で有効化

## 作業内容

GitHub Actions ランナー上で Codex / Claude Code から Context7 MCP を使えるようにした。

- ワークフローの Setup secrets ステップに `VV_CONTEXT7_API_KEY` Secret の処理を追加
- Claude Code 用: `~/.claude.json` に `mcpServers` を HTTP 方式で生成
- Codex 用: `$VV_CODEX_HOME/config.toml` に `[mcp_servers.context7]` を生成
- `_extract_mcp_domains()` で `~/.claude.json` の MCP サーバー URL からドメインを抽出し、`sandbox.network.allowedDomains` に自動マージ
- `_DENY_READ_PATHS` に `~/.claude.json` を追加し、AI プロセスからの API キー読み取りを遮断
- README の Secrets 表に `VV_CONTEXT7_API_KEY` を追加

## レビュー内容

3回のレビューを受けた。

- レビュー1回目: SHOULD-FIX 1件。`_extract_mcp_domains()` の except ブロックでログを出していない → stderr に出力するよう修正
- レビュー2回目: SHOULD-FIX 1件。`if url:` が falsy/truthy チェックで規約違反 → `if url != "":` に修正
- レビュー3回目: NOTE 1件のみ。`_extract_mcp_domains` のフォールバック挙動について。stderr ログ済みで規約を満たしている → 修正不要と判断

## 見逃しの考察

- except ブロックでのログ出力漏れ: フォールバックとして空リストを返す場合にログが必要という規約を把握していたが、実装時に「ファイルが存在しない場合は正常系」という意識が先行し、パースエラー時のログまで思い至らなかった
- falsy/truthy チェック: `if url:` は Python では自然な書き方だが、プロジェクト規約で厳密比較が求められている。規約チェックを実装後に行う習慣が不足している

## 手こずったこと

なし。ワークフローの heredoc インデントと YAML リテラルブロックスカラーの相互作用を慎重に確認したが、問題なく動作する構造だった。
