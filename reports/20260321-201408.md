# Report

## Summary
CLI と GitHub event payload を受ける入力モデルを追加し、`vv-ai` の入口から共通の `RawInput` を組み立てられる状態にした。レビューで見つかった `--event-file` 単独実行と `@vv-ai` prefix 誤判定の不具合もあわせて修正した。

## Changes
- `src/vv_ai/input.py` を追加し、CLI 入力モデル、共通 `RawInput`、`issue_comment` / `workflow_dispatch` の最小 payload モデルを実装した。
- `@vv-ai ...` コメント本文を字句的に分解し、command、provider、session、dry-run、instruction を抽出する処理を追加した。
- `workflow_dispatch` の `inputs` から `target_number`、`dry_run` などを基本型へ変換する処理を追加した。
- `src/vv_ai/cli.py` を更新し、各入力オプションを `argparse` で受けて `RawInput` 生成まで接続した。
- `--event-file` と直接指定引数の併用をエラーにし、`--event-file` 単独時は payload から event 種別を推定するようにした。
- `@vv-ai-bot` のような prefix だけ一致するコメントを拒否する境界チェックを追加した。
- `plan.md` の「CLI / event payload を受ける入力モデルを定義する」を完了済みに更新した。

## Decisions
- このタスクでは入力の受理と型変換に集中し、コマンドごとの必須条件や target 解決は次の正規化タスクへ分離した。
- GitHub event payload は必要項目だけを読む最小モデルにとどめ、余剰フィールドは無視する方針にした。
- `--event-file` はデバッグや再現実行の使い勝手を優先し、`--event` 未指定時は payload から自動判定するようにした。

- `UV_CACHE_DIR=/tmp/uv-cache uv run python -m compileall src`

## Risks / Open Questions
- `RawInput` から `ResolvedCommand` への必須項目判定、`target_url` 優先、event-file と直接引数の詳細整合はまだ未実装で、次タスクで詰める必要がある。
- `workflow_dispatch` payload の実フィールド差分は今後の workflow 実装時に再確認が必要で、必要なら最小モデルを増やす余地がある。

## Next Actions
- 次の未完了タスクである「`RawInput` から `ResolvedCommand` への正規化を実装する」に着手する。
- command ごとの必須/任意項目、`target_url` 優先、対象不足時のエラーを正規化層へ実装する。
- `allowed_users` と provider 優先順位の解決をその次の入力確定フローへ接続する。
